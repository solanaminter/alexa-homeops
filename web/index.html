🏗 How it works

How this deployed demo is wired (honest version). A persistent MCP server can't run on plain static hosting, so this site's /api/* endpoints are lightweight serverless functions (web/api/) that re-implement the offline demo path: the same deterministic intent router and the same 16-tool semantics as src/homeops/, operating on the real bundled seed data (web/data/household.json, copied from the repo's sample_data/household.json). State is per-instance and resets on cold start — use “Reset demo state” to reseed. The full-fidelity backend (Python MCP server + Strands agent, Streamable HTTP, persistent hash-chained audit) runs locally: python -m homeops.server + python web/bridge.py. See the repo README.

🛡 Trust & governance

The differentiator: least-privilege scopes, a human-in-the-loop gate for consequential actions, and an immutable audit trail — all first-class primitives, live in the demo above.

🔑 Scoped permissions

Every tool declares the scopes it needs. Calls without them are denied explicitly — never silently. The demo grants the full set; set HOMEOPS_SCOPES to narrow it (e.g. calendar:read) and watch writes get denied.

✋ Human approval gate

Consequential actions return approval_required instead of executing. The action only runs via approvals_decide after a human approves — denials leave state untouched. Try it: delete the PTA meeting, then deny.

⛓ Hash-chained audit log

Every call is appended with prev_hash → entry_hash (SHA-256), so tampering is evident. audit_get_log replays and verifies the chain on every read — the panel above shows it live.
